Building Kinship: High-Performance Family Tree Canvas with React Flow & Supabase

Kinship is a modern, full-stack lineage visualization platform engineered around an interactive infinite panning and zooming canvas. It eliminates the clunky, tangled trees typical of legacy genealogy software by introducing automated symmetric marriage junctions, collision-free sibling row alignment, persistent spatial coordinate memory, and granular collaborator permissions powered by Supabase.

🌐 Live App: familytree-livid.vercel.app 💻 GitHub Repository ⚖️ MIT License

The Problem: The Geometric Complexity of Genealogy Graphs

Family trees are deceptive. While superficially resembling standard hierarchical trees (like organizational charts or file systems), genealogical graphs are Directed Acyclic Graphs (DAGs) with bidirectional lateral constraints:

  • Spouse Pairing Dilemma: Two unrelated nodes (spouses) must sit on the exact same vertical tier, joined horizontally, without pushing other branches out of scope.
  • Line-Crossing Chaos: Children belong equally to two parents. In naive force-directed layouts, connection lines cross directly over other family members, quickly becoming an unreadable "spaghetti graph."
  • Loss of Spatial Mental Models: Most web visualizers recalculate node coordinates on every browser refresh. Users lose their visual bearings because grandparents and cousins jump to completely arbitrary screen positions.

1. Symmetric Marriage Junction Algorithm

In Kinship, spouses are not linked with messy intersecting bezier curves. Instead, a dedicated, invisible-yet-snappable Marriage Junction Node is dynamically injected into the graph between married partners:

The junction node calculates its position precisely halfway between both partners along the X axis, positioned slightly below their node baseline: 

// Dynamic marriage junction coordinate calculator
export function calculateMarriageJunction(partnerA, partnerB, verticalGutter = 48) {
  const midX = (partnerA.position.x + partnerB.position.x) / 2;
  const midY = Math.max(partnerA.position.y, partnerB.position.y) + verticalGutter;

  return {
    id: `junction-${partnerA.id}-${partnerB.id}`,
    type: 'marriageJunction',
    position: { x: midX, y: midY },
    data: { spouses: [partnerA.id, partnerB.id] },
    selectable: false,
    draggable: false,
  };
}

All shared children then connect directly to this single junction node via "Comb" orthogonal edge routing. This guarantees zero edge intersections between spouses and eliminates visual clutter.

2. Sibling Row Alignment & Collision Avoidance

When a couple has multiple children, placing them manually can be tedious. Kinship incorporates an automated sibling alignment pass:

  • Subtree Bounding Box Calculation: Determines the cumulative width of each child's own downstream descendants.
  • Single-Row Equal Distribution: Arranges all direct siblings on a uniform horizontal plane with predictable padding (e.g., 220px gutter between cards).
  • Lineage Centering: Centers the sibling row directly beneath the parental marriage junction, ensuring clean bilateral symmetry.

3. Spatial Persistence & Database Architecture

Unlike temporary chart viewers, Kinship preserves exact user layout customizations. Every person in the family tree stores their x and y canvas coordinates directly in Supabase PostgreSQL: 

-- Kinship Database Schema (Supabase PostgreSQL)
CREATE TABLE public.people (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    full_name TEXT NOT NULL,
    birth_date DATE,
    death_date DATE,
    gender TEXT CHECK (gender IN ('male', 'female', 'other')),
    photo_url TEXT,
    notes TEXT,
    x FLOAT DEFAULT NULL, -- Spatial Canvas Coordinates
    y FLOAT DEFAULT NULL,
    branch_id UUID REFERENCES public.family_branches(id) ON DELETE CASCADE,
    created_at TIMESTAMPTZ DEFAULT now()
);

CREATE TABLE public.relationships (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    person_a UUID REFERENCES public.people(id) ON DELETE CASCADE,
    person_b UUID REFERENCES public.people(id) ON DELETE CASCADE,
    type TEXT DEFAULT 'parent' CHECK (type IN ('parent', 'spouse', 'sibling')),
    created_at TIMESTAMPTZ DEFAULT now()
);

Users can freely reposition nodes on the canvas. As soon as a node drag finishes, the updated coordinate pair is debounced and synced to Supabase via Row Level Security (RLS) policies.

4. Multi-Tenant Branch Sharing & RBAC

Genealogy is collaborative. Kinship supports multi-tenant branch ownership and granular collaborator invitations through branch_shares:

  • Viewer Role: Allows distant relatives to pan, zoom, inspect member bios, and view photos without altering the lineage structure.
  • Editor Role: Empowers trusted family members to add new generations, update dates, attach media, and refine relationships.
  • Invitation State Machine: Collaborator requests maintain clean pending, accepted, and declined status transitions.

5. High-Resolution Vector & Document Export

Families love printing wall charts and archival books. Kinship integrates html2canvas and jspdf to capture the entire active graph viewport:

  • Calculates the global bounding box enclosing all family nodes.
  • Temporarily scales the canvas pixel ratio (2x or 3x) to render ultra-sharp text and photos.
  • Compiles the output directly into a multi-page PDF or a high-res PNG poster suitable for physical framing.
