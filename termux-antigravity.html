Building Android Apps Without a Laptop: Compiling CleanFiles on Device with Termux, Ubuntu & Antigravity CLI

What if you didn’t need a laptop to build Android apps at all? No bulky workstation, no 12GB Android Studio setup, and no cloud build servers. Just an Android smartphone, a terminal app, a small Linux layer, and an AI coding agent compiling native code right in your hands.

🔗 LinkedIn Post Android Native (ARM64) Termux + Ubuntu 24.04 PRoot Antigravity CLI Agent 42 KB Signed APK

The Spark: Can a Phone Replace a Laptop?

This experiment started when my friend shared an interesting idea: what if we ran the Antigravity CLI directly on an Android phone using Termux, and turned the phone itself into a complete development environment?

Today’s smartphones are remarkably fast. Modern phone processors are easily as capable as many laptops were just a few years back. Still, almost everyone assumes building an Android app requires a computer with a heavy IDE like Android Studio, gigabytes of build tools, and constant emulator testing.

I was curious to see if that was actually true, or if we just do it out of habit. So I decided to test it myself: install Termux, set up an Ubuntu environment inside it, configure the Antigravity CLI agent, and see if I could write, compile, and run a real native app without touching a computer once.

Why I Built CleanFiles: Escaping the Ads

I didn't want to build just another generic demo app; I wanted to solve an annoying problem I deal with every day. Like a lot of Android users, I was tired of the default file manager that came pre-installed on my phone. A basic utility that should just open folders and show downloaded files had become completely loaded with ads: full-screen popups, banner ads taking up screen space, random 'app recommendations', and unnecessary permission requests.

Every time I needed to find a downloaded PDF, move camera photos, or clean up storage, I had to wait through an ad or be careful not to accidentally tap sponsored links.

So the goal became clear: use this mobile setup to build CleanFiles—a clean, fast, and completely ad-free file manager with zero bloat and total privacy, built and compiled right on the phone.

The Workflow

Android → Termux → Ubuntu 24.04 → Antigravity CLI → Native Project → APK

No laptop. No USB debugging cables. No remote servers. The phone itself wrote the code, packaged the resources, compiled the Java classes into Dalvik bytecode, signed the package, and installed the finished app right onto its own operating system.

Phase 1: Setting Up the Mobile Linux Environment

Standard Android development uses Gradle, which downloads gigabytes of dependencies and easily overwhelms a mobile phone's memory. Instead, we used a lightweight, headless command-line toolchain inside Ubuntu 24.04 via PRoot:

  • Termux & PRoot: Termux gives us a standard terminal, while proot-distro installs a clean Ubuntu 24.04 LTS Linux system with standard library support.
  • Java Compiler: openjdk-17-jdk-headless for fast Java compiling without any graphical bloat.
  • Android Build Tools: Standalone ARM64 command-line tools: aapt (packaging), d8 (dex compiler), zipalign, and apksigner alongside android.jar (API 33).
  • Storage Access: Running termux-setup-storage gives the terminal permission to read and write directly to the phone's internal storage (like the /sdcard/Download folder).

Phase 2: Designing CleanFiles with the AI Agent

I gave the prompt to Antigravity CLI straight from the phone's terminal. We worked through the project layout together, and let the agent create the files.

We designed CleanFiles with the essential features a good file manager needs:

  • Live Storage Overview: Checking storage space in real time down to the byte, with a visual progress bar (like 56.3 GB used out of 64 GB, 87%).
  • Quick Category Breakdown: Fast scanning across the device to calculate how much space is taken up by Photos, Videos, and Audio.
  • Folder Navigator: Easy tabbed browsing between Internal Storage, Downloads, and Recent Files with item counts and clear folder icons.
  • Zero Ads & Complete Privacy: Built using only standard Android SDK components—no tracking scripts, no third-party ad networks, and instant launch times.

Phase 3: The 5-Step Headless Compilation Sequence

Antigravity CLI organized the build steps, checked the manifest, and ran the whole compilation sequence right in the terminal. Here is the actual terminal screenshot showing the agent running each command:

Step 1: Resource Packaging (aapt)

Compiling app icons, layouts, and values into the resource table and generating the R.java file: 

# Compile resources and generate R.java
aapt package -f -m     -J /root/CleanFiles/src     -M /root/CleanFiles/AndroidManifest.xml     -S /root/CleanFiles/res     -I /opt/android-sdk/platforms/android-33/android.jar

Step 2: Java Compilation (javac)

Compiling all Java source files (activities, storage scanners, and R.java) into standard Java bytecode: 

mkdir -p /root/CleanFiles/build/classes
javac -d /root/CleanFiles/build/classes     -cp /opt/android-sdk/platforms/android-33/android.jar     $(find /root/CleanFiles/src -name "*.java")

Step 3: Creating Dalvik Bytecode (d8)

Converting the Java .class files into Android's native Dalvik executable format (classes.dex): 

mkdir -p /root/CleanFiles/build/dex
d8 /root/CleanFiles/build/classes/com/cleanfiles/app/*.class     --lib /opt/android-sdk/platforms/android-33/android.jar     --output /root/CleanFiles/build/dex

Step 4: Packaging and Memory Alignment (aapt & zipalign)

Packing the classes.dex file and resources into an APK, then aligning it on 4-byte boundaries so the Android OS can load it quickly: 

# Package initial unaligned APK
aapt package -f     -M /root/CleanFiles/AndroidManifest.xml     -S /root/CleanFiles/res     -I /opt/android-sdk/platforms/android-33/android.jar     -F /root/CleanFiles/build/cleanfiles-unaligned.apk     /root/CleanFiles/build/dex

# Align on 4-byte boundaries for fast loading
zipalign -p -f 4     /root/CleanFiles/build/cleanfiles-unaligned.apk     /root/CleanFiles/build/CleanFiles.apk

Step 5: Signing the APK (apksigner)

Signing the final APK with an on-device security key using modern Android signing schemes (v1, v2, and v3): 

apksigner sign --ks /root/release.keystore     --ks-key-alias release     --ks-pass pass:android     /root/CleanFiles/build/CleanFiles.apk

The result? A super-lightweight, native Android app measuring just 42 KB—smaller than almost any image on a modern website!

Phase 4: Installing and Running the App on Device

One of the coolest parts of the whole experiment was installing the app. Usually with a laptop, you connect a USB cable, turn on USB debugging, and run adb install.

In our setup, the agent simply copied the signed APK to the phone's Download folder and called a Termux command to trigger Android's native installer: 

# Copy signed APK to the phone's Download directory
cp /root/CleanFiles/build/CleanFiles.apk /sdcard/Download/CleanFiles.apk

# Tell Android to open and install the APK
termux-open /sdcard/Download/CleanFiles.apk

Right away, the phone's standard "Do you want to install this app?" dialog popped up on screen. With one tap, CleanFiles was installed and running live on the very phone that wrote and compiled it.

The Realities: What Worked and What Was Difficult

While the experiment worked surprisingly well, developing on a phone isn't about to replace a dual-monitor desktop setup just yet. A few practical realities came up:

  • Typing on a Touchscreen: Entering commands, editing long paths, and selecting text with a virtual keyboard gets tiring quickly. If you want to do serious work this way, a small Bluetooth keyboard makes a huge difference.
  • Setting Up the Tools: Getting the Android command-line tools to play nicely inside an Ubuntu PRoot layer on Android takes some initial setup and patience with system paths.
  • Battery and Heat: Running an AI agent, compiling Java code, and packaging the APK puts real load on the phone's processor. It warms up the device and drains the battery faster than normal usage.
  • Checking the Code: Even with an agent helping you, you still need to review the code, catch layout mistakes, and verify that Android permissions are configured properly.

Key Takeaways: Building Software Anywhere

Despite the small challenges, the takeaway from this project is genuinely exciting:

  1. The Barrier to Building Has Dropped: You don't need a high-end computer or gigabytes of desktop software to create working native apps. A regular smartphone in your pocket can brainstorm, write code, compile it, and run the finished product.
  2. AI Agents Can Work in Minimal Environments: Autonomous coding agents aren't limited to desktop code editors. When given access to a terminal, they can run compilers, fix build errors, and complete full development cycles independently.
  3. True Computing Freedom: Whether you want to fix a bug on a train or build a quick tool while away from your desk, your phone is fully capable of being an actual creation tool.
